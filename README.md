# Shadow Reading

以文章为主线的英语影子学习工作台：反复精听、逐段理解、跟读和复述，把文章里的表达用于自己的生活。

## 当前内容

- **40 篇精编文章**：20 个原主题重写、10 篇长访谈、10 篇新增叙事/问题解决文章；每篇约 300–390 词，共约 1.4 万个英文词次。
- 每篇包含 **6 组中英对齐段落、4 个文章表达讲解、2 道具体理解题、1 个复述任务和 1 个迁移任务**。支持按题材、文体、难度搜索筛选。
- **20 篇历史原稿**保留原文、原顺序、ID 和段落锚点；重写稿使用独立 ID，不继承原稿的完成标记。
- **17 个词汇专题、303 个用法条目**，用于巩固文章中出现的动词、数字、形容词、时间等基础表达。
- **40 个短对话**作为补充练习，保留原有听写、角色接话与迁移流程。

精编文章为原创教学文本，人物和场景为虚构；访谈不是对真实人物的采访。基础/中级/进阶为编辑难度提示，未做标准化等级评定。词次、用法条目与已掌握单词数量分开计算，不宣称覆盖全部英语词汇。

## 使用

线上地址：[Shadow Reading](https://aramisjiang-wq.github.io/shadow-reading/)。同一浏览器访问此地址可继续使用原站本地学习记录；本机地址与线上地址的记录分开保存，需要时先导出完整备份，再到线上导入。

打开 `index.html`，或在此目录运行：

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

访问 <http://127.0.0.1:8765>。本机服务或 HTTPS 支持麦克风权限；设备需要提供英文合成音色。主工作台无需外部字体、翻译服务或账号即可使用，录音不上传。

推荐从今日阅读或文章库选一篇，按 **精听 → 双语理解 → 逐句/逐段跟读 → 文章表达 → 理解检查 → 复述与迁移** 练习。同一篇可以反复练习；文章末尾可查看语言点、关联词汇专题并保存复述/迁移自评。短对话和独立词汇回忆是辅助练习。

文章理解题只显示本轮结果；它不会将文章标为掌握。文章复述/迁移以 `article:编号:任务` 保存到统一学习记录和完整备份，文本可在回到同一文章时恢复。

- 语境填空按参考答案核对，忽略标点、大小写和多余空格。它不是自由表达的语义评分器。
- 看过答案/提示后答对记为辅助练习；未看提示答对才记独立回忆。
- 未辅助答对后的间隔为 1、3、7、14、30 天，同日重复不会连续升级。答错或看提示后仍需巩固。
- 角色接话与迁移表达保存自评，不自动评判发音、语法或掌握程度。迁移题有多种合理答案。
- 朗读使用浏览器合成语音，不是真人录音。设备不支持时会显示说明，不能完成的朗读不会增加听完记录。
- 录音只在本练习暂存，可下载；切换页面/练习方式会停止麦克风并清除临时录音。

## 数据与兼容

学习记录保存在当前浏览器、当前网站来源下，不自动同步到其他设备。**更换端口、域名、浏览器或从文件模式改为服务模式，可能看到另一份本地存储。** 迁移前请从原来源导出完整备份。

新版使用 `sr_learning_v1` 保存不可变练习事件。原 `sr_wordStatus`、`sr_completed`、`sr_practiced` 等键保留，原“掌握”文字明确为“自评掌握”。旧 `index.html?article=N&paragraph=M` 自动转到 `reading.html` 的同一篇同一段。

三个页面的导出统一为 v4 完整备份，含新版课程记录与原单词、文章、段落记录。支持 v1–v4 备份导入，先验证再合并：保留已有单词自评，文章/段落取并集，练习按事件 ID 去重。损坏/冲突备份不会写入；写入失败会尝试回滚。多标签写入在支持 Web Locks 的浏览器中串行处理；不支持此 API 的旧浏览器请避免同时在多个标签练习。

存储异常会显示提示。可在学习记录页导出存储原件作为恢复资料；原件不等同于可直接导入的学习备份。音频不进入 JSON 备份。

## 验证

Node.js 20+，开发依赖只用于检查，不影响静态页面运行：

```sh
npm ci
npx playwright install chromium
npm test
npm run test:browser
npm run test:articles
npm run test:ui
```

浏览器测试前启动本机服务，默认访问 8765 端口；可通过 `TEST_URL` 指定其他地址。文章流程检查另运行 `node tests/article-browser.cjs`。检查结果与人工审查见 `docs/article-verification-2026-11-02.md`；早期辅助练习检查见 `docs/verification-2026-11-02.md`。浏览器检查包含受控语音错误/取消路径，不替代真实设备音色和录音质量验收。

## 界面设计

首页、文章库、阅读器与辅助页面使用同一套暖白/绿色视觉、深浅主题和本地字体。首页突出继续阅读与文章预览，文章库支持搜索、题材与版本筛选。阅读器提供正文、语言点、理解与复述三个区域，统一播放器与阅读设置，手机目录可搜索与关闭。

参考 LingQ 的内容组织、Readlang 的语境查词、Readwise Reader 的听读控制、Beelinguapp 的双语阅读。公开一手来源、观察范围和具体取舍见 [UI 案例调研](docs/ui-reference-review-2026-11-02.md)，检查结果见 [UI 验证记录](docs/ui-verification-2026-11-02.md)。这些案例是按场景适配选择，并非产品排名。

## 内容维护

原始 `articles-data.js` 保留前 20 篇。`editorial-data.js` 追加 ID 21–60 的 40 篇精编稿；ID 21–40 对应旧主题 1–20，`revisionOf` 表达同主题重写关系。扩充时只追加新 ID，不重新排序底层数组，以保留按索引存储的旧记录。

完整双语正文与练习在 `Shadow-Reading-English-Materials.md`。修改数据后运行 `node scripts/export-reading-materials.cjs`，同步材料文档。`tests/original-articles-fingerprints.json` 验证历史原稿未被改写，内容测试检查所有新稿的段落、表达和答案引用。

## 发布

`npm run build` 将明确列出的网页、脚本、样式、图标和教学材料复制到 `dist/`，并生成版本及提交标识 `release.json`。开发依赖、测试截图、文档和学习备份样本不进入网站发布包。

`main` 的应用更新触发唯一的 GitHub Pages 工作流；内容与学习状态测试通过后，对发布包在 `/shadow-reading/` 子目录运行三套浏览器检查，全部通过才部署。单独更新 `docs/` 或本 README 不重复部署。工作流也可手动触发。

发布后核对线上 `release.json`、文章库和阅读器。必要时可重新运行上一成功部署记录以恢复上一版网站；学习数据保存在浏览器中，网站回滚不清除记录。历史版本的功能只识别其支持的记录字段，因此回滚前应导出完整备份。
