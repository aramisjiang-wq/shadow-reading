# 文章学习 UI 优化 Implementation Plan

**Goal:** 保持文章为主线，降低选择、听读、查词和复述中的操作干扰，统一首页、内容库、阅读器和辅助页面的视觉与移动体验。

**Architecture:** 延用原生 HTML/CSS/JS 和既有学习记录、事件与文章索引；不迁移框架。新增共享设计令牌、阅读器外观层和必要交互适配，保留稳定 DOM ID 与可回归验证的功能。

**Tech Stack:** CSS variables / Grid、语义 HTML、原有 Web Speech/MediaRecorder、Node 与 Playwright。

## 案例依据

- LingQ 官方内容库/阅读器介绍：https://www.lingq.com/blog/introducing-lingq-5-0/ 。已查看官方历史截图；这是 5.0 介绍，不视为当前登录版逐屏验收。参考继续学习、题材书架、收敛阅读工具与逐句学习。
- Readlang：https://readlang.com/ 。查看公开功能说明和划词示意，参考不中断正文的就地词汇辅助。
- Readwise Reader：https://docs.readwise.io/reader/docs/faqs/text-to-speech 。参考暂停/停止的明确区别、阅读中的播放器。公开宣传截图受浏览器限制，未绕过访问，也不声称实测登录版。
- Beelinguapp：https://beelinguapp.com/ 。已查看官方手机界面，参考原文/译文清楚分层、当前朗读突出及文章后练习。

## 设计决定

主方向为安静的阅读应用。保留暖白、墨色、低饱和绿，减少大面积装饰与零值数据；正文采用书籍式衬线字、约 60–70 字符的行宽，界面使用清晰的无衬线。桌面紧凑导航、移动端明确底部入口；文章库采用可扫描的条目布局与有辨识度的原创题材图形。

不照搬其他产品的付费、AI 云能力、自动掌握判断或账户体系。所有文章文字、ID、旧稿指纹、备份格式和学习状态语义保持。

## 实施与验收

1. 共享 4/8/12/16/24/32/48 间距、字级、边框、圆角和深浅主题；本地图形与图标不依赖外站加载。
2. 首页突出继续阅读，显示文章实际进度与预览；统计为辅助。文章库统一搜索筛选、条目信息层级和空结果清除入口。
3. 阅读器正文优先，固定播放器；常用播放、段落、速度、译文有文字/可访问标签；字体、音色等次要项集中到设置。手机能看到段落操作，词典不越界。
4. 原文、表达、理解/复述切换与定位清楚；保留全部正文和任务，长辅助内容按需展开。输入草稿不因视觉切换丢失。
5. 辅助词汇、复习、记录和历史单词本统一视觉；减少表情图标和装饰阴影。
6. 跑既有 16 个内容/状态测试、两套浏览器回归，加 UI 检查：320/390/768/1440 视口、深浅主题、键盘焦点、译文/查词/播放/切篇/备份/草稿。

重点不变量：视觉切换不能产生学习成绩；原文与旧标记不漂移；播放器控制与实际状态相符；浮层/固定播放器不遮挡输入和最后一项内容；查看/切换辅助区域不丢失已输入草稿。
